# 前言

大模型的书已经很多了。大多数从算法讲起：注意力怎么推导、训练怎么收敛、微调怎么做。这些内容重要，但它们回答不了工程师最常遇到的问题——为什么这个 kernel 只有 15% 的利用率，为什么 70B 模型在 8 张卡上只能跑 10 毫秒一个 token，为什么扩到 128K 上下文之后并发从 150 掉到 5。

这本书从系统讲起。它把 LLM 当成一个需要被调度、被优化、被运维的计算负载：先算清楚它要多少 FLOPs、多少字节、多少通信，再看这些数字在硬件上如何变成时间，最后讨论怎么把它们压下去。

## 为什么写这本书

LLM 系统的知识目前散落在三类材料里：论文讲机制但不讲工程，框架源码讲实现但不讲取舍，博客讲技巧但不讲体系。读者往往在某个点上很深，却拼不出完整的图景——知道 FlashAttention 怎么分块，却说不清它和 KV Cache、batch 调度、SLO 之间的关系。

本书试图把这些点连成线。每一章都尽量给出可计算的模型：一个公式、一个数量级、一个可以自己验算的算例。数字会过时，硬件会换代，但“先估算再优化”的方法不会。

## 与已有资料的区别

- **以系统为主线**：模型结构、数值格式、kernel、显存、调度、并行、训练、服务，按“一次请求经过的路径”组织，而不是按学科分支；
- **以数量级为目标**：每个结论都尽量落到具体数字上，并说明这些数字是怎么算出来的、在什么假设下成立；
- **以 C++/CUDA 为实践语言**：关键机制给出代码结构和数据结构，而不只是框图；
- **承认边界**：讲不清的地方明确说讲不清，不给“取决于具体情况”这种没有信息量的结论。

## 写给谁

有 C++、操作系统、GPU 或分布式系统背景，希望理解并实现 LLM 底层系统的工程师。

读这本书不需要会训练模型，但需要能读懂矩阵乘法的形状、能理解 cache 和带宽、能接受用估算代替精确测量。

## 这本书不是什么

- 不是 LLM 应用开发指南。RAG、Agent、Tool Calling 只在讨论它们对 Runtime 和 Serving 的系统需求时出现。
- 不是以神经网络算法为主线的机器学习教材。反向传播、优化器理论只讲到能理解系统开销为止。
- 不是某一种硬件的编程手册。CUDA 是主要实践平台，但性能模型尽量保持平台无关。
- 不是产品评测或选型报告。书中出现的型号和参数只用于估算，不构成推荐。

## 如何使用这本书

全书 10 个 Part、50 章，按“基础 → 计算 → 数值 → kernel → 推理 → 分布式 → 训练 → 后训练 → 编译与服务 → 前沿”排列。可以顺序读，也可以按角色选读：

- **做推理系统的**：Part I、III、IV、V、VI、IX 是主线；
- **做训练基础设施的**：Part I、VI、VII 是主线，Part IV 提供 kernel 基础；
- **做模型与算法的**：Part II、III、VIII 能补齐系统视角；
- **只想知道“为什么慢”的**：Chapter 3、5、6 加上对应场景的章节即可。

每章末尾有小结和延伸阅读。小结里的条目是这一章最值得记住的结论，延伸阅读给出可以继续深入的原论文。

## 约定

- 正文用中文，技术术语首次出现时给出中英文对照，之后以英文为主；
- 公式用 LaTeX 表示；模型权重、显存等大容量用十进制 GB 标注，KV 块等小粒度用 KiB/MiB；
- 代码以 C++17 和 CUDA 12 为基准，Python 只用于示意；
- 所有性能数字都标注了硬件和假设，换一个环境结果会不同。
